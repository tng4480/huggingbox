## What’s new

- Codex CLI and Claude Code generation/repair using existing CLI sign-in; no API key required in HuggingBox for these providers.
- Prepare once and reuse setup and loaded model components between runs, with explicit unload and repair controls.
- Persistent prompts/workspaces, task shortcuts, and saved-run comparison/export.

## Reliability fixes

- Removing managed weights preserves scripts, results, and legacy downloads.
- Download only selected runtime/quantisation files; pin revisions and validate completed caches. Generated recipes use the local prepared weights.
- Stop cancels preparation and prevents late execution; failed preparation remains retryable.
- Scope output events to jobs; preserve running work during navigation and reject stale metadata responses.
- Use shared/custom environments consistently; fix GGUF generation, generic inference, and CPU selection.
- Reject unsupported diffusion GGUF routes explicitly; clarify RAM-fit estimates.

## Validation and limits

28 automated tests passed locally, covering frontend workflows, Python runtime behavior and native storage/CLI handling. Generated Python compiled for 28 runtime/hardware combinations. A real offline Qwen model and repeated native app runs succeeded; a signed-in Codex CLI smoke test also succeeded.

Claude Code requires installing and signing in locally; its integration was tested with fixtures, but a live Claude Code request was not verified. Windows installers are built and regression-tested by GitHub Actions; GPU execution still requires hardware validation. Arbitrary Hub architectures are not guaranteed to work.

Existing custom scripts are preserved. Re-gen creates a backup and adopts the new local-cache recipe contract. Gated Hugging Face models still need Hugging Face access. Fine-tuning and J-lens are not included in this release.
